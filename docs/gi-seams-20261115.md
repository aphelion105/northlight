# GI continuity, terrain interpolation and seams

Inspected `session-35940-403756390-0`, captures 1–4, and the supplied screenshot.
The other two latest sessions contain weather metadata only. These are native
Northlight diagnostics, not RenderDoc captures. Private inspection artifacts
and buffer hashes are under `.local/out/gi-seams-20261115/`.

Captures 1/2 isolate GI and record strength 2 and brightness -1. Their lighting
buffers already show the bright stipples, facet edges and broad patches before
final composition. Their exported normals and distances are all zero, so those
exports cannot establish normal/depth correspondence. Captures 3/4 have usable
normals: respectively 60,833 and 50,041 surface pixels have zero confidence and
a non-upward normal; 55,246 and 43,537 of these lie beyond view distance 180.
Their local-light input exports explicitly say incomplete, and none exports the
GI probe atlas. This is buffer inspection, not a complete replay or a measured
before/after game image.

Three code paths reproduced the reported failures:

- The missing-probe fallback interpolated back to full ambient whenever normal
  confidence was zero. Facet/silhouette uncertainty therefore drew bright seams
  through otherwise dark walls. It now uses the existing one-sided normal for
  sky orientation; uncertain positive bounce remains suppressed.
- Solved probes inside terrain shared the missing-probe metadata value. Their
  trilinear weights reduced coverage, blending ambient into a fully solved cell
  as the surface crossed the eight-unit lattice. Metadata now distinguishes
  missing from solved invalid points. Invalid points establish coverage while
  their moment validity still excludes radiance. Missing cells, wrapped keys
  and first-residency fading retain their separate behavior.
- On a same-map BVH refresh, display fallback retained SH but deleted its
  visibility. The shader interpreted that pair as completely blocked until the
  worker solved the point again. Display fallback now retains the whole sample;
  replacement caches still start fresh and never consume fallback values.

The existing retention policy can display an old sample until its replacement
is ready, including its old blockers. It does not establish current geometry
for an unsolved point. Map changes and exact-key replacement remain boundaries.

`test_gi_residency_gpu.py` exercises production metadata upload and shader
evaluation on system D3D9, DXVK2 and DXVK3. It sweeps positions across a cell
with solid corners, missing corners, fully invalid corners, wrapped metadata,
activation fading, brightness -1/0 and confident/uncertain normals. Analytical
expected values and a shader with the old behavior provide independent checks.
`test_progressive_gi_worker.py` executes the production worker tail, including
same-map BVH replacement, repeated camera requests, immutable publication and
negative controls that deliberately discard visibility or final fallback.
Its Windows path uses Zig; host sanitizer coverage remains on the host-compiler
path. Activation and byte-exact padded texture packing run in the same driver.

Run the strict source, architecture and GPU suites against the final tree and
build with `python scripts/build_renderer.py`. Acceptance JSON must verify
against that tree. Installation consists of the matching `d3d9.dll` and
`northlight-assets.bin`, with the previous pair backed up. No release or package
publication is part of this change. Live-game appearance after restart remains
separate from the deterministic CPU/GPU checks.

## Follow-up: directional receiver seams

The next log confirms source `b5cd2fd7` and its matching assets were loaded.
Session `session-40184-407058625-0`, captures 1/2, uses shadow debug mode
(`PassInfo.z=1`). Capture 3 includes usable depth, normals and directional maps.
The remaining terrain lines are present in directional visibility independently
of GI. The previous GI checks did not establish that these shadow seams were fixed.

Two receiver issues contribute: zero shading confidence disabled the receiver
plane even for a valid one-sided normal, and a filtered normal spans different
facets at a sharp join. Shadow receivers now retain the plane of valid normals
and add a bounded depth allowance where adjacent, depth-continuous normals bend.
The allowance follows the light ray; increasing the normal displacement instead
can cross the opposite wall of a concave join. Sky and depth breaks are excluded,
and flat receivers retain their existing offsets. Both direction-transition
epochs use the same receiver rule.

`test_shadow_receiver_gpu.py` uses an analytical height field under vertical
light, a concave crease, an independent blocker, and a different-depth neighbour.
The old shader is a negative control. It checks confidence independence, unchanged
flat shadow edges, retained blockers and removal of crease self-shadowing on
system D3D9, DXVK2 and DXVK3. PCSS samples keep their order; compact loops share
the transition comparison so the existing instruction limits remain enforced.

`scripts/analyze_shadow_receivers.py` replays supplied shader bytecode on the
exported depth/maps. It does not reproduce actors, temporal filtering or final
composition. On the inspected terrain ROI `[100,140,790,890]` of capture 3,
pixels below visibility .95 decreased from 2,587 to 388, and summed occlusion
from 707.84 to 97.94. These measurements localize the improvement; they do not
prove that every remaining dark pixel is an artifact or establish gameplay FPS.
Artifacts and input hashes are in `.local/out/gi-seams-followup-20261115/`.
