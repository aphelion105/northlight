# Runtime delivery audit for Windows 0.3.218

Audited 2026-11-13 against the runtime file consumers in `src/`, the live client
root, package payload/APP_FILES and installer generation paths. The release is
built from committed sources; game-specific caches and art are generated by the
packaged tools from the target client's archives.

| Runtime input or feature | Delivery |
|---|---|
| `d3d9.dll` | Production DLL, embedded source identity checked against the current runtime tree. Includes shadow fixes, material optimizations, HDR sky/Outland emission, lunar sizing and camera-stable sand shelter handling. |
| `northlight-assets.bin` | Required NLA1 sidecar, paired to the DLL by SHA-256. Contains shader bytecode, weather textures/mips and overlay font. |
| `forever-atmosphere.bin` | Explicit NFA2 payload added in this release; main-continent light, fog and sky tables. Hash/counts in BUILD-INFO and payload manifest; installed and rolled back transactionally. |
| `celestial-profiles.ini`, `shadow-range-profiles.ini`, `northlight-quality.ini` | Current factory profiles in the payload; existing user settings are preserved/migrated by the installer. |
| `northlight-renderer.ini` | Created/merged for the selected backend by `windows-package/install.py`; it is intentionally not copied from the developer's client. |
| DXVK backends | Both pinned DXVK 3.1.1 and 2.7.1 with licenses. System D3D9/legacy backend selection remains supported. |
| `world-cache/<map>/*.fg3`, `models/*.fgs` | Scene builder shipped; cached per target archive chain. |
| `world-cache/lights/*`, `native-fixtures.bin`, attachment/point-transmission data | Light/fixture/attachment builders and their profiles ship in APP_FILES. |
| `world-cache/fog/*/*.frf` | Regional generator ships with forest and expansion region tables. Covers Azeroth, Kalimdor, Expansion01 and Northrend. |
| `world-cache/celestial/sun.fct`, `moon.fct` | Generated from the target client's celestial artwork by the packaged celestial builder. |
| `northlight-emission.bin` | Generated by `emission_catalog.build()` during the art-layer build, included in its install/rollback transaction. Not interchangeable between different client asset packs. |
| `northlight-art-inputs.ini` | Generated with the target client's archive fingerprint; used by the runtime guard. |
| `Data/patch-z.mpq`, locale `patch-<locale>-z.mpq` | Generated art layer: lighting, sky cleanup, emission/model changes and weather assets. Both outputs are verified and installed transactionally. |
| Outland/Northrend atmosphere, emissive and celestial adaptations | Compiled runtime rules plus packaged `expansion_atmosphere.h`, lighting profiles and generators. The NFA2 file itself only contains maps 0/1. |

## Missing delivery paths corrected

The converted NFA2 was previously only a separate local install. It now has an
explicit package-builder input (`--forever-atmosphere`) and release asset; a
normal installation of this release no longer depends on copying it manually.

The regional fog builder had gained expansion indoor exclusion bounds without
changing fog cache revision 1. An update could therefore retain older FRF files
even with the new generator present. Fog revision is now 2, and
`expansion_atmosphere.h` is included in its recorded source provenance. The
regression test requires a revision-1 cache to plan only `partial: fog`, retaining
scene, lights and celestial caches. Art-layer inputs then see the updated fog
files through their existing fingerprint path. This is a cache compatibility
revision, not a new quality setting.

## Files that are not missing runtime dependencies

`fogdata.bin` belongs to another renderer; Northlight does not read it. Raw
Forever DB2/BLP research, unsupported grading/particle experiments, screenshots,
logs, diagnostics, rollback folders and third-party client DLLs are not Northlight
runtime inputs. `northlight-emitter-patch.json` is a build/investigation report,
not the runtime emission catalog. Cache manifests and instance selections are
generated for each install.

The live INIs contain personal overrides (including diagnostics and disabled
water effects) and some older celestial/shadow-region entries. They were compared
semantically with the package profiles; the release ships the current factory
profiles and preserves existing choices rather than promoting the developer's
preferences to everyone's defaults. Development tuning files are only for the
separate tuning DLL and are not production assets.

The package verifier checks APP_FILES byte equality, import closure, pinned
runtimes/backends, payload hashes and DLL/resource pairing. The converted NFA2
also passes the actual C++ table loader/key/weather tests. This audit does not
claim a full cache/art rebuild on every supported client variant.
