## Findings

1. **Two owners of the sun.** The material catalog calls `pogost_sun.blp`,
   `arathi_sun.blp`, `stormwind_sun.blp`, independent lunar discs and authored
   sun rays foreground clouds. Their native geometry keeps its own placement,
   while Northlight uses the selected orbit. Native planet identity suppression
   cannot suppress a separate M2 material. Such materials also contaminate the
   cloud-transmission buffer.
2. **Black replacement source.** A valid black native tint is copied into the
   replacement disc and into its HDR core. This correctly records native state
   but incorrectly treats the skybox's disabled billboard as zero solar energy.
   Multiplying emission by any gain cannot repair a zero tint.
3. **Incomplete colour import.** NFA1 stores direct and ambient colours but
   consumers ignore them. Sky gradient, SunColor and CloudSunColor are omitted.
   Native HD sky and native light bands therefore determine the palette.
4. **Anisotropy changes total energy.** The imported volume uses HG divided by
   its forward peak. For g=0.9 the sphere-average response is 1/190. Large g
   consequently almost extinguishes shafts away from the exact source axis.
   Restore the HG phase with unit sphere-average response (isotropic g=0 is 1).
5. **Material direction inconsistency.** `materialLight()` uses native daytime
   direction while its moon path uses selected direction. Native direction must
   remain available for removal of baked light, but new highlights must follow
   the selected source.
6. **Capture boundary.** Existing world captures stop before late celestial
   composition. An unclipped HDR disc must be checked with the production
   celestial GPU oracle; do not describe the world snapshot as a final frame.

7. **Late HDR source bypassed volume extinction.** The HDR celestial pass ran
   after world fog composition. It now writes the decoded HDR base before the
   world pass; the disc, glow and background share the same atmosphere, and the
   existing world capture includes the source before its extinction.

## Implementation order and contracts

1. Give explicitly reviewed skybox sun/moon/flare/ray materials a celestial
   role. Suppress them only with a valid replacement renderer; F10/debug and
   failed resource paths retain native rendering. Never suppress unknown
   materials or cloud textures by filename heuristics at runtime. Regenerate
   the catalog from local client archives, with ambiguity checks.
2. Keep native records truthful; choose a nonzero replacement tint when the
   native appearance is black. Import SunColor/CloudSunColor when available.
   Sun disk, halo, volume and new material light use the selected orbit.
3. Extend the local atmosphere format with six sky gradient colours and two
   solar colours, retaining NFA1 compatibility. Interpolate by the existing
   time/location/weather weights. Replace only the captured sky background;
   retain foreground cloud/horizon transmission and existing HDR residual.
   Default/Forever remains the placement/size selector, independent of the
   imported atmosphere. Outland/Northrend retain their authored approximations.
4. Use energy-preserving HG scattering with unchanged extinction and shadow
   tests. No global exposure/bloom multiplier to disguise missing source energy.
5. Validate black native tint, catalog ownership/fallback, source direction,
   versioned import and periodic interpolation, anisotropy energy and production
   HDR/occlusion/cloud shaders. Run source and architecture suites, relevant GPU
   checks with the normal game-process guard, shader freshness and production
   build. Install only the verified DLL/data with backups and unchanged INIs.

## Acceptance limits

from initialized executable tables. The rendering algorithm, tone mapping,
cloud assets and expansion atmospheres are Northlight implementations, not a
verified pixel-identical reconstruction of Forever. Final artistic comparison
requires a new in-game frame at Tirisfal 18:04 and Hillsbrad 18:12. Existing
capture is around 12:54 and cannot prove those reference-time matches.

## Results

Implemented the seven corrections above. The local NFA2 file has 216 lights,
2374 time keys and 17 outlines, plus 2374 eight-colour sky records. Its original
NFA1 payload layout is retained; version 2 appends the sky records. Existing NFA1
files still load and retain the native sky background.

The new background pass reconstructs foreground + replacement background times
transmission. SDR writes this encoded colour; HDR adds the signed difference
between decoded new and decoded native colour, retaining existing HDR emission.
Only clear-depth sky pixels change. Six latitude bands are a Northlight
approximation: the extracted colours are exact data, the original Forever dome
geometry is not copied. Imported direct light drives the selected sources;
imported ambient drives GI. Native illumination remains available for removal
of the client's baked light. Shadow direction retains the existing low-sun
6-degree floor and subsecond smoothing; this is a near-horizon approximation.

Validation evidence is under `.local/out/sky-audit-20261112/`:

- Source suite: 9/9. Architecture suite: 7/7.
- Direct Windows Zig CPU runs passed for native context, black native sun tint,
  palette application and imported NFA2 data. The generic runner's `cxx` probe
